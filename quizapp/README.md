# Quiz Application Backend

A single monolithic Spring Boot backend for a Quiz application. Java 17 + Spring Boot + Spring Data JPA + MySQL.
No authentication, no microservices, no security layer — the `/api/admin/*` and `/api/user/*` prefixes exist only
to separate the two Appzillon screens.

---

## 1. Prerequisites

- Java 17
- Maven 3.8+
- MySQL 8.x running locally (or reachable)

## 2. Configure the database

Edit `src/main/resources/application.properties` and set your MySQL password:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/quiz_app?createDatabaseIfNotExist=true&useSSL=false&serverTimezone=UTC
spring.datasource.username=root
spring.datasource.password=YOUR_PASSWORD
```

The database `quiz_app` is created automatically (`createDatabaseIfNotExist=true`), and tables
(`quizzes`, `questions`, `quiz_attempts`, `user_answers`) are generated by Hibernate on first run
(`spring.jpa.hibernate.ddl-auto=update`).

## 3. Build and run

```bash
mvn clean install
mvn spring-boot:run
```

The app starts on `http://localhost:8080`.

## 4. API Reference

All endpoints use only `@PathVariable` and `@RequestBody` — no query/request parameters.

### Admin — Quiz CRUD

| Method | URL | Body |
|---|---|---|
| POST | `/api/admin/quizzes` | `QuizRequest` |
| GET | `/api/admin/quizzes` | — |
| GET | `/api/admin/quizzes/{quizId}` | — |
| PUT | `/api/admin/quizzes/{quizId}` | `QuizRequest` |
| DELETE | `/api/admin/quizzes/{quizId}` | — |

**Create quiz — request**
```json
POST /api/admin/quizzes
{
  "title": "Java Basics",
  "category": "Java",
  "duration": 10,
  "totalMarks": 10
}
```

**Create quiz — response (201 CREATED)**
```json
{
  "id": 1,
  "title": "Java Basics",
  "category": "Java",
  "duration": 10,
  "totalMarks": 10
}
```

| Method | URL | Body |
|---|---|---|

| GET | `/api/admin/quizzes/{quizId}/questions` | — |

| PUT | `/api/admin/questions/{questionId}` | `QuestionRequest` |

**Add question — request** (`quizId` comes from the URL, not the body)
```json
POST /api/admin/quizzes/1/questions
{
  "questionText": "Which keyword is used to inherit a class?",
  "optionA": "implements",
  "optionB": "extends",
  "optionC": "super",
  "optionD": "this",
  "correctAnswer": "B",
  "marks": 1
}
```

**Add question — response (201 CREATED)**
```json
{
  "id": 1,
  "quizId": 1,
  "questionText": "Which keyword is used to inherit a class?",
  "optionA": "implements",
  "optionB": "extends",
  "optionC": "super",
  "optionD": "this",
  "correctAnswer": "B",
  "marks": 1
}
```

### User — Attempt a quiz

| Method | URL | Body |
|---|---|---|
| POST | `/api/user/quizzes/{quizId}/start` | — |
| POST | `/api/user/attempts/{attemptId}/submit` | `SubmitQuizRequest` |
| GET | `/api/user/attempts/{attemptId}/result` | — |

**Start quiz — response**
```json
POST /api/user/quizzes/1/start
{
  "attemptId": 1,
  "quizId": 1,
  "startedAt": "2026-08-26T12:00:00",
  "duration": 10
}
```

**Submit quiz — request** (only `questionId` + `selectedAnswer`, never score/marks/correctAnswer)
```json
POST /api/user/attempts/1/submit
{
  "answers": [
    { "questionId": 1, "selectedAnswer": "B" },
    { "questionId": 2, "selectedAnswer": "A" },
    { "questionId": 3, "selectedAnswer": "C" }
  ]
}
```

**Submit quiz — response** (score/percentage calculated server-side)
```json
{
  "attemptId": 1,
  "quizId": 1,
  "score": 8,
  "totalMarks": 10,
  "percentage": 80.0,
  "status": "SUBMITTED",
  "submittedAt": "2026-08-26T12:10:00"
}
```

**Get result — response**
```json
GET /api/user/attempts/1/result
{
  "attemptId": 1,
  "quizId": 1,
  "score": 8,
  "totalMarks": 10,
  "percentage": 80.0,
  "status": "SUBMITTED",
  "submittedAt": "2026-08-26T12:10:00"
}
```

### Error format (all error responses)

```json
{
  "success": false,
  "message": "Quiz not found"
}
```

| Situation | Status |
|---|---|
| Resource not found (quiz/question/attempt) | 404 NOT FOUND |
| Bad request (invalid quiz/question/answer, already submitted, validation errors) | 400 BAD REQUEST |
| Success (create) | 201 CREATED |
| Success (read/update/delete) | 200 OK |

## 5. Business rules implemented

1. **Cannot submit twice** — submitting an already-`SUBMITTED` attempt returns `400` with
   `"Quiz attempt has already been submitted"`.
2. **Question must belong to quiz** — a `questionId` in the submit request that isn't part of the
   attempt's quiz is rejected with `400`.
3. **Valid answer** — `selectedAnswer` (and `correctAnswer`) are restricted to `A`/`B`/`C`/`D` via
   Bean Validation `@Pattern`.
4. **Unanswered questions** — any quiz question not present in the submitted `answers` list simply
   contributes `0` marks (it is never scored as correct).
5. **Backend-controlled scoring** — `score`, `percentage`, and `marksObtained` are always computed
   in `QuizAttemptService` by comparing the stored `correctAnswer` against the submitted
   `selectedAnswer`. The frontend cannot influence these values.

## 6. Postman testing instructions

1. Import a new Postman collection (or create requests manually) pointed at `http://localhost:8080`.
2. **Admin flow**
   - `POST /api/admin/quizzes` → copy the returned `id` (this is your `quizId`).
   - `POST /api/admin/quizzes/{quizId}/questions` → repeat for each question, copy each returned `id`
     (these are your `questionId`s).
   - `GET /api/admin/quizzes/{quizId}/questions` to confirm.
3. **User flow**
   - `GET /api/user/quizzes` to browse.
   - `GET /api/user/quizzes/{quizId}` to view questions (note: no `correctAnswer` field).
   - `POST /api/user/quizzes/{quizId}/start` → copy the returned `attemptId`.
   - `POST /api/user/attempts/{attemptId}/submit` with a body listing `questionId` + `selectedAnswer`
     for each question you answered.
   - `GET /api/user/attempts/{attemptId}/result` to re-check the score at any time.
4. **Negative tests**
   - Re-submit the same `attemptId` → expect `400` "Quiz attempt has already been submitted".
   - Submit a `questionId` from a different quiz → expect `400`.
   - Submit a `selectedAnswer` of `"E"` → expect `400` validation error.
   - `GET /api/admin/quizzes/9999` → expect `404` "Quiz not found".

## 7. Appzillon API mapping

| Appzillon screen | API call |
|---|---|
| Admin Dashboard → list quizzes | `GET /api/admin/quizzes` |
| Admin → Create Quiz form submit | `POST /api/admin/quizzes` |
| Admin → Edit Quiz form submit | `PUT /api/admin/quizzes/{quizId}` |
| Admin → Delete Quiz button | `DELETE /api/admin/quizzes/{quizId}` |
| Admin → Add Question form submit | `POST /api/admin/quizzes/{quizId}/questions` |
| Admin → Questions list for a quiz | `GET /api/admin/quizzes/{quizId}/questions` |
| Admin → Edit Question form submit | `PUT /api/admin/questions/{questionId}` |
| Admin → Delete Question button | `DELETE /api/admin/questions/{questionId}` |
| User → Quiz List screen | `GET /api/user/quizzes` |
| User → Select Quiz / view questions | `GET /api/user/quizzes/{quizId}` |
| User → "Start Quiz" button | `POST /api/user/quizzes/{quizId}/start` |
| User → "Submit" button (collects selected options) | `POST /api/user/attempts/{attemptId}/submit` |
| User → Score / Result screen | `GET /api/user/attempts/{attemptId}/result` (or the submit response directly) |

Appzillon should call these via its standard server-call / REST connector mechanism, no
Appzillon-specific code lives in the Spring Boot backend.

## 8. Project structure

```
com.example.quizapp
├── QuizApplication.java
├── controller   (AdminQuizController, AdminQuestionController, UserQuizController)
├── dto          (request/response DTOs)
├── entity       (Quiz, Question, QuizAttempt, UserAnswer, AttemptStatus)
├── repository   (Spring Data JPA repositories)
├── service      (QuizService, QuestionService, QuizAttemptService — all business logic here)
└── exception    (ResourceNotFoundException, BadRequestException, ErrorResponse, GlobalExceptionHandler)
```
